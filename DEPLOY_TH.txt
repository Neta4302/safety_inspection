SafeCheck — คู่มือการนำระบบขึ้นออนไลน์ (Deployment Guide)
================================================================================
เอกสารนี้ใช้สำหรับส่งงานครั้งที่ 3 หัวข้อ "Source Code and Deployment Link"

  *** ลิงก์ที่ใช้งานจริง (Deployment Link) ***
      https://safety-inspection.onrender.com

  *** Source Code ***
      https://github.com/Neta4302/safety_inspection

  นำขึ้นระบบเมื่อ 10 ก.ย. 2569 · Render (Singapore) · แผน Free · Node.js 24.11.0
  ผลการตรวจสอบหลังนำขึ้นระบบ: HTTPS ใช้งานได้ · session cookie มีแฟล็ก Secure ·
  การแบ่งสิทธิ์ตามบทบาททำงานเหมือนกับตอนรันในเครื่องทุกประการ

สถาปัตยกรรมการติดตั้ง
--------------------------------------------------------------------------------
  ผู้ใช้ (เบราว์เซอร์ / มือถือ)
        |  HTTPS
        v
  Render (TLS proxy)  ---- x-forwarded-proto / x-forwarded-for --->  Node.js
                                                                     (server.js)
                                                                        |
                                                                        v
                                                                  SQLite
                                                              (data/safecheck.db)

  - Render เป็นผู้ถอดรหัส HTTPS แล้วส่งต่อเป็น HTTP ภายในเครือข่ายของตัวเอง
  - ระบบจึงต้องตั้งค่า TRUST_PROXY=true เพื่อให้รู้ว่าอยู่หลัง proxy จริง
    (ถ้าไม่ตั้ง cookie จะไม่มีแฟล็ก Secure และตัวจำกัดการล็อกอินจะนับ IP ผิด)


ขั้นตอนที่ 1 — สร้างบัญชี GitHub และ Repository
--------------------------------------------------------------------------------
  1. สมัคร/เข้าสู่ระบบที่  https://github.com
  2. กดปุ่ม  New repository
  3. ตั้งชื่อ เช่น  safecheck
  4. เลือก  Public   (Render แผนฟรีอ่าน repo สาธารณะได้ง่ายที่สุด
                      และอาจารย์เปิดดู source code ได้ตามที่โจทย์กำหนด)
  5. อย่าติ๊ก "Add a README" — เพราะเรามีไฟล์อยู่แล้ว
  6. กด  Create repository  แล้วคัดลอก URL ที่ได้ เช่น
       https://github.com/<ชื่อผู้ใช้>/safecheck.git


ขั้นตอนที่ 2 — อัปโหลดโค้ดขึ้น GitHub
--------------------------------------------------------------------------------
  เปิด Git Bash หรือ Command Prompt ที่โฟลเดอร์
      Safety_Inspection_Demo\Safety_Inspection_Demo
  (โฟลเดอร์ชั้นในที่มีไฟล์ server.js) แล้วรันทีละคำสั่ง:

      git init
      git add .
      git commit -m "SafeCheck: fire safety inspection system"
      git branch -M main
      git remote add origin https://github.com/<ชื่อผู้ใช้>/safecheck.git
      git push -u origin main

  หมายเหตุ: ไฟล์ .gitignore จะกันไม่ให้โฟลเดอร์ data/ ถูกอัปโหลด
  เพราะข้างในมีฐานข้อมูลจริงซึ่งเก็บรหัสผ่านที่เข้ารหัสไว้และไฟล์หลักฐานที่อัปโหลด
  ระบบจะสร้างฐานข้อมูลใหม่พร้อมข้อมูลตัวอย่างให้เองเมื่อเริ่มทำงานครั้งแรก


ขั้นตอนที่ 3 — สร้างบริการบน Render
--------------------------------------------------------------------------------
  1. สมัคร/เข้าสู่ระบบที่  https://render.com  (สมัครด้วยบัญชี GitHub ได้เลย)
  2. กด  New +  ->  Web Service
  3. เลือก repository  safecheck  ที่เพิ่งสร้าง
  4. ตรวจสอบค่าต่อไปนี้ (ปกติ Render จะอ่านจากไฟล์ render.yaml ให้อัตโนมัติ)
         Runtime         : Node
         Build Command   : npm install
         Start Command   : node server.js
         Instance Type   : Free
  5. เลื่อนลงไปที่หัวข้อ  Environment Variables  แล้วเพิ่ม 2 ตัวนี้ให้ครบ
         NODE_VERSION  =  24
         TRUST_PROXY   =  true
     ** NODE_VERSION สำคัญมาก ถ้าไม่ตั้ง Render จะใช้ Node รุ่นเก่ากว่า
        ซึ่งเปิดโมดูล node:sqlite ไม่ได้ และระบบจะไม่ยอมเริ่มทำงาน **
  6. กด  Create Web Service  แล้วรอประมาณ 2-4 นาที
  7. เมื่อขึ้นสถานะ  Live  จะได้ลิงก์หน้าตาแบบนี้
         https://safecheck-xxxx.onrender.com
     นี่คือ "Deployment Link" ที่ต้องส่งอาจารย์


ขั้นตอนที่ 4 — ตรวจสอบว่าใช้งานได้จริง
--------------------------------------------------------------------------------
  [ ] เปิดลิงก์แล้วเห็นหน้าเข้าสู่ระบบ
  [ ] เข้าสู่ระบบด้วย  admin@safecheck.demo  /  Demo1234!  ได้
  [ ] กล่อง "ขอบเขตข้อมูลของคุณ" แสดงว่าเห็นครบ 6 สถานประกอบการ
  [ ] ลองเข้าด้วย  inspector@safecheck.demo  แล้วเห็นแค่ 2 แห่ง (ระบบสิทธิ์ทำงาน)
  [ ] เปิดลิงก์เดียวกันบนมือถือ แล้วหน้าจอย่อขยายได้ถูกต้อง
  [ ] ที่อยู่เว็บขึ้นเป็น  https://  (ไม่ใช่ http)


ข้อจำกัดของแผนฟรีที่ต้องรู้ก่อนนำเสนอ
--------------------------------------------------------------------------------
  1. เซิร์ฟเวอร์จะ "หลับ" เมื่อไม่มีคนใช้งานประมาณ 15 นาที
     การเปิดครั้งถัดไปจะช้าประมาณ 50 วินาที
     -> ก่อนนำเสนอหรือก่อนส่งลิงก์ให้อาจารย์ ให้เปิดลิงก์ทิ้งไว้ล่วงหน้า 1 นาที
     -> วันนำเสนอจริงยังคงใช้ Start-SafeCheck.bat บนเครื่องตัวเอง จะเร็วและไม่มีความเสี่ยง

  2. พื้นที่เก็บไฟล์ของแผนฟรีไม่ถาวร เมื่อเซิร์ฟเวอร์รีสตาร์ท
     ฐานข้อมูลจะถูกสร้างใหม่พร้อมข้อมูลตัวอย่างชุดเดิม
     ข้อมูลที่กรอกทดสอบไว้จะหายไป แต่ระบบยังใช้งานได้ปกติทุกอย่าง
     -> จะแก้ถาวรด้วยการย้ายไปใช้ PostgreSQL หลังส่งงานครั้งที่ 3

  3. ลิงก์นี้เปิดสาธารณะ ใครมีลิงก์และรู้รหัสบัญชีทดลองก็เข้าใช้ได้
     ซึ่งเป็นเจตนาอยู่แล้วเพื่อให้อาจารย์เข้าตรวจได้
     แต่ควรทราบว่าบัญชี admin มีสิทธิ์กดรีเซ็ตข้อมูลได้
     -> ถ้าต้องการ สามารถเปลี่ยนรหัสผ่านบัญชี admin แล้วแจ้งอาจารย์เฉพาะราย


ความปลอดภัยที่ได้เพิ่มขึ้นจากการขึ้นออนไลน์
--------------------------------------------------------------------------------
  - รหัสผ่านถูกส่งผ่าน HTTPS ที่เข้ารหัสแล้ว (ตอนรันในเครือข่าย Wi-Fi ภายใน
    ด้วย http ธรรมดา รหัสผ่านจะถูกดักอ่านได้)
  - Session cookie ได้แฟล็ก Secure อัตโนมัติเมื่อทำงานผ่าน HTTPS
  - ตัวจำกัดจำนวนครั้งการล็อกอินอ่าน IP จริงของผู้ใช้จาก x-forwarded-for
    ทำให้ผู้ใช้คนละคนไม่ถูกนับรวมกันเป็น IP เดียว
