SafeCheck - Functional Web Demo (พร้อมฐานข้อมูล SQLite จริง)
================================================================

วิธีเปิดใช้งาน — แบบง่ายที่สุด (แนะนำ)
1. แตกไฟล์ทั้งหมดไว้ในโฟลเดอร์เดียวกัน
2. ดับเบิลคลิกไฟล์  Start-SafeCheck.bat
   เซิร์ฟเวอร์จะเริ่มทำงานและเปิดเบราว์เซอร์ให้เองอัตโนมัติ ไม่ต้องพิมพ์คำสั่งใด ๆ
   ** อย่าปิดหน้าต่างสีดำระหว่างนำเสนอ เพราะเป็นตัวรันระบบอยู่ **
3. เข้าสู่ระบบด้วยบัญชีทดลอง — กดที่กล่อง “บัญชีทดลองสำหรับสาธิต” แล้วคลิกบัญชีที่ต้องการ
   ระบบจะกรอกอีเมลและรหัสผ่านให้อัตโนมัติ จากนั้นกด “เข้าสู่ระบบ”

วิธีเปิดใช้งาน — แบบพิมพ์คำสั่งเอง (ยังใช้ได้เหมือนเดิม)
   เปิด Terminal/Command Prompt ในโฟลเดอร์ Safety_Inspection_Demo แล้วรัน:
     node server.js
   จากนั้นเปิดเบราว์เซอร์ไปที่ http://localhost:4173

ใช้งานบนมือถือ / แท็บเล็ต
   ระบบรองรับหน้าจอทุกขนาดอยู่แล้ว (คอมพิวเตอร์ โน้ตบุ๊ก แท็บเล็ต และมือถือ)
   วิธีเปิดบนมือถือ:
     1. ต่อมือถือเข้า Wi-Fi วงเดียวกับคอมพิวเตอร์ที่รันระบบอยู่
     2. ดูบรรทัด “on this network:” ที่แสดงในหน้าต่างสีดำ เช่น  http://192.168.1.118:4173
     3. พิมพ์ที่อยู่นั้นในเบราว์เซอร์บนมือถือ
   (ต้องอยู่ Wi-Fi วงเดียวกัน เพราะระบบรันอยู่บนเครื่องคอมพิวเตอร์ ไม่ได้อยู่บนอินเทอร์เน็ต)

ต้องมี Node.js เวอร์ชัน 22.5 ขึ้นไป — ไม่ต้องต่ออินเทอร์เน็ต ไม่ต้อง npm install
ถ้ายังไม่มี Node.js ให้ดาวน์โหลดรุ่น LTS จาก https://nodejs.org แล้วติดตั้งก่อน

หมายเหตุ: โปรเจกต์นี้ไม่มี dependency ภายนอกเลย (ใช้ node:sqlite ที่มากับ Node
โดยตรง) จึงไม่จำเป็นต้องรัน npm install ก่อนใช้งาน ฐานข้อมูลจะถูกสร้างและ
ใส่ข้อมูลตัวอย่างให้อัตโนมัติที่ data/safecheck.db ในการรันครั้งแรก

ลำดับการนำเสนอต่ออาจารย์ (ตอบครบทั้ง 7 ข้อที่อาจารย์คอมเมนต์ · ประมาณ 8-10 นาที)
--------------------------------------------------------------------------------
ก่อนเริ่ม: ดับเบิลคลิก Start-SafeCheck.bat · เข้าสู่ระบบด้วย admin@safecheck.demo (รหัส Demo1234!)
           ** ต้องใช้บัญชี admin เพราะเป็นบัญชีเดียวที่มีสิทธิ์ครบทุกอย่างสำหรับสาธิต **
           เตรียมรูปภาพและวิดีโอสั้น 1 ไฟล์ไว้ในเครื่องสำหรับสาธิตการแนบหลักฐาน
           ถ้าเคยกดเล่นไว้แล้วให้กด “รีเซ็ตข้อมูลเดโม” ก่อน

[ข้อ 1: มาตรฐาน] เปิดเมนู “มาตรฐานความปลอดภัย” — ชี้ให้เห็นเลขมาตรฐาน แหล่งอ้างอิง
        และคอลัมน์ “เกี่ยวข้องกับ” ที่โยงมาตรฐานแต่ละฉบับเข้ากับรหัสรายการตรวจ (DLY/MON/YRL)

[ข้อ 7: CCTV] เปิด “สถานะ AI แบบเรียลไทม์” — อธิบายแผนภาพว่า CCTV เป็นเพียงอุปกรณ์รับภาพ
        ไม่ใช่ตัว AI  ลำดับคือ CCTV → AI Module → Alert Engine → แจ้งเตือน

[ข้อ 2: AI ตรวจจับอะไร] หน้าเดียวกัน — ชี้ตาราง 4 ประเภทความผิดปกติที่ตรวจจับ และตาราง
        “เกณฑ์ตัดสินไม่ปลอดภัย/เสี่ยง” (Confidence ≥ 80%, กีดขวาง ≥ 50%, ค้าง ≥ 30 วินาที, อยู่ใน Zone)
        จากนั้นกด “จำลองการตรวจจับ” เพื่อแสดง Flow: ตรวจจับ → ประมวลผล → จัดระดับ → แจ้งเตือน
        แล้วกด “ดูรายการนี้ →” เพื่อกระโดดไปยังการแจ้งเตือนที่เพิ่งเกิดขึ้น

[ข้อ 3: ระดับการแจ้งเตือน] หน้า “การแจ้งเตือน Safety” — อธิบายการ์ด 3 ระดับ (ปกติ / ค่อนข้างเข้าข่าย /
        อันตราย) ว่าแต่ละระดับระบบทำอะไร  แล้วสาธิตการทวีระดับ: กด “จำลองหมดเวลา (ไม่รับทราบ)”
        จะเห็นสถานะเปลี่ยนเป็น “ทวีระดับแจ้งหัวหน้าแล้ว”  เทียบกับการกด “พนักงานรับทราบ”

[ข้อ 4: อุปกรณ์] เปิด “เซ็นเซอร์ & อุปกรณ์” — ตารางเปรียบเทียบอุปกรณ์ 6 ชนิด พร้อมเหตุผลที่เลือก
        และภาพอุปกรณ์สภาพปกติ  กด “จำลองตรวจสอบภาพด้วย AI” เพื่อแสดงการช่วยตรวจอุปกรณ์ชำรุด
        จากนั้นเปิด “ทะเบียนอุปกรณ์” — ตารางเทียบจำนวนถังดับเพลิงกับมาตรฐาน (1 ถัง : 10 โต๊ะ)
        กด “จำลองจัดซื้อ” ที่แถวซึ่งขาด และกด “จำลองอ่านวันหมดอายุจากภาพ”

[ข้อ 6: UI ครบทุกหน้า] ไล่เมนูด้านซ้ายให้เห็นครบ 12 หน้า: Dashboard, เริ่มการตรวจ, แบบตรวจ,
        สรุปผล, ประวัติการตรวจ, ติดตามการแก้ไข, สถานะ AI, การแจ้งเตือน, เซ็นเซอร์, ทะเบียนอุปกรณ์,
        มาตรฐาน, การทดสอบระบบ (+ หน้ารายงานสำหรับพิมพ์)

[ข้อ 5: การทดสอบ] เปิด “การทดสอบระบบ” — สภาพแวดล้อมที่ทดสอบ ข้อมูลที่เก็บ และตารางเกณฑ์
        ผ่าน/ไม่ผ่านที่เป็นตัวเลขชัดเจน (Precision ≥ 90%, False Positive ≤ 10%, แจ้งเตือน ≤ 5 วินาที)

จุดขายเพิ่มเติมที่ควรโชว์ท้ายการนำเสนอ
  • กดปุ่มสลับภาษา EN/ไทย ที่มุมขวาบน — เปลี่ยนทั้งระบบทันทีโดยไม่เสียข้อมูลที่กรอกไว้
  • ปิดเซิร์ฟเวอร์แล้วเปิดใหม่ ข้อมูลยังอยู่ครบ — พิสูจน์ว่าเป็นฐานข้อมูลจริง ไม่ใช่เก็บในเบราว์เซอร์
  • กรอกรหัสผ่านผิด 5 ครั้ง จะถูกระงับชั่วคราว 10 นาที — พิสูจน์ระบบป้องกันการเดารหัสผ่าน

ลำดับสาธิตที่แนะนำ (ประมาณ 3-5 นาที) — ฝั่งตรวจสอบโดยเจ้าหน้าที่
1. เปิด Dashboard และอธิบายสถิติภาพรวม รวมถึงแบนเนอร์ “สำหรับคุณ” ที่เปลี่ยนตามบทบาท
2. เลือก “เริ่มการตรวจ” เลือก Riverlight Bistro แล้วเลือกความถี่ (รายวัน/รายเดือน/รายปี)
3. ตอบ Checklist ให้ครบ โดยเลือก “ไม่ผ่าน” อย่างน้อย 1 ข้อ เพื่อดูว่าระบบบังคับแนบรูปภาพ
   สำหรับข้อที่ evidence จำเป็น (กรอบสีแดง) ต่างจากข้อที่แนบได้ตามต้องการ
4. เพิ่มหมายเหตุหรือรูปภาพตัวอย่าง แล้วกดส่งผลการตรวจ
5. เปิดหน้าติดตามการแก้ไข และเปลี่ยนสถานะรายการ
6. เปิดประวัติการตรวจ (จะเห็นแท็กความถี่ของแต่ละรายการ) และรายงาน จากนั้นกด “พิมพ์ / บันทึก PDF”

ลำดับสาธิตที่แนะนำ — ฝั่งตรวจจับด้วย AI & CCTV (เมนู “ตรวจจับด้วย AI & CCTV”)
1. เปิด “สถานะ AI แบบเรียลไทม์” อธิบายว่าระบบเน้นตรวจจับความผิดปกติที่เกี่ยวข้องกับ
   อัคคีภัยโดยเฉพาะ (Fire Disaster Focus) และบทบาทของ CCTV เทียบกับโมดูล AI
2. กด “จำลองการตรวจจับ” เพื่อแสดงขั้นตอน ตรวจจับ → ประมวลผล → จัดระดับ → แจ้งเตือน
   ระบบจะสุ่มประเภทความผิดปกติ (สิ่งกีดขวาง/ควัน/ถังดับเพลิงหาย/ป้ายถูกบัง) ทุกครั้ง
3. กด “ดูรายการนี้ →” ในผลลัพธ์ เพื่อกระโดดไปหน้าการแจ้งเตือนพร้อมไฮไลต์รายการที่เพิ่งสร้าง
4. เปิดหน้า “การแจ้งเตือน Safety” อธิบาย 3 ระดับ (ปกติ/ค่อนข้างเข้าข่าย/อันตราย) ลองกด
   “พนักงานรับทราบ” หรือ “จำลองหมดเวลา” เพื่อดูการทวีระดับถึงหัวหน้า แล้วสลับแท็บไปดู “ประวัติทั้งหมด”
5. เปิด “เซ็นเซอร์ & อุปกรณ์” อธิบายฮาร์ดแวร์แต่ละชนิดและกด “จำลองตรวจสอบภาพด้วย AI”
6. เปิด “ทะเบียนอุปกรณ์ & อายุการใช้งาน” อธิบายตารางเปรียบเทียบจำนวนถังดับเพลิงกับมาตรฐาน
   (1 ถังต่อ 10 โต๊ะ) กด “จำลองจัดซื้อ” ที่แถวซึ่งอุปกรณ์ไม่พอ และกด “จำลองอ่านวันหมดอายุจากภาพ”
7. เปิด “มาตรฐานความปลอดภัย” และ “การทดสอบระบบ” เพื่ออธิบายเอกสารอ้างอิงและแผนทดสอบ

หลักฐานภาพและวิดีโอ (Evidence Media)
- แต่ละรายการตรวจแนบไฟล์ได้สูงสุด 3 ไฟล์ จะเป็นรูปภาพหรือวิดีโอก็ได้ (ผสมกันได้)
- รูปภาพไม่เกิน 5 MB (JPG/PNG/WEBP) · วิดีโอไม่เกิน 20 MB (MP4/WEBM/MOV)
- เลือกหลายไฟล์พร้อมกันได้ หากเกินโควตาระบบจะรับเท่าที่เหลือและแจ้งจำนวนที่รับได้
- ไฟล์เก็บในตาราง media ของฐานข้อมูล (ไม่ฝังลงในข้อมูลการตรวจ) หน้าเว็บจึงโหลดเร็ว
  เพราะดึงไฟล์เฉพาะตอนแสดงผลผ่าน /api/media/:id และต้องเข้าสู่ระบบก่อนจึงจะดูได้
- ระบบตรวจสอบชนิดไฟล์และขนาดที่ฝั่งเซิร์ฟเวอร์ด้วย ไม่ได้เชื่อถือเฉพาะฝั่งหน้าเว็บ

การเข้าสู่ระบบ (Login / Signup)
- ระบบมีหน้าเข้าสู่ระบบและสมัครสมาชิกจริง เก็บผู้ใช้ในตาราง users ของฐานข้อมูล
- รหัสผ่านถูกเข้ารหัสด้วย scrypt + salt (ไม่เก็บรหัสผ่านแบบข้อความธรรมดา)
- บัญชีทดลอง 5 บทบาท รหัสผ่าน Demo1234! ทุกบัญชี — กดที่รายการบัญชีในหน้า Login
  เพื่อกรอกอัตโนมัติ (ยังต้องเข้าสู่ระบบจริง ไม่ใช่การข้ามระบบยืนยันตัวตน)
     inspector@safecheck.demo   / safety@safecheck.demo
     supervisor@safecheck.demo  / manager@safecheck.demo / admin@safecheck.demo
- ความปลอดภัย: การสมัครสมาชิกเองสร้างได้เฉพาะบทบาท Inspector และ Safety Officer
  ส่วนบทบาท Supervisor / Manager / Administrator ต้องให้ผู้ดูแลระบบกำหนดให้เท่านั้น
  (ป้องกัน Privilege Escalation — ตรวจสอบที่ฝั่งเซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนใน UI)

รองรับ 2 ภาษา (ไทย / English)
- กดปุ่มสลับภาษา (EN / ไทย) ที่มุมขวาบน หรือที่การ์ดเข้าสู่ระบบ
- สลับได้ทันทีทุกหน้า รวมถึงระหว่างกรอกแบบตรวจ โดยไม่สูญเสียข้อมูลที่กรอกไว้
- ระบบจำภาษาที่เลือกไว้ แม้ปิดแล้วเปิดใหม่
- แปลครบทั้งเมนู ฟอร์ม ตาราง รายงาน เอกสารมาตรฐาน และข้อความแจ้งเตือนจาก AI

ข้อมูลสำคัญ
- ระบบนี้เป็น MVP สำหรับการสาธิต
- ข้อมูลเก็บถาวรในฐานข้อมูล SQLite (data/safecheck.db) บนเครื่องที่รันเซิร์ฟเวอร์ —
  ปิด/เปิดเซิร์ฟเวอร์ใหม่ข้อมูลจะยังอยู่ครบ (ต่างจากเดิมที่เก็บใน Browser Local Storage)
- ทำงานได้โดยไม่ต้องเชื่อมต่ออินเทอร์เน็ต (เซิร์ฟเวอร์รันบน localhost เท่านั้น)
- หากต้องการเริ่มใหม่ เลือก “รีเซ็ตข้อมูลเดโม” ที่เมนูด้านซ้าย (ล้างและสร้างข้อมูลตัวอย่างใหม่)


สิทธิ์การเข้าถึงตามบทบาท (Role-Based Access Control)
--------------------------------------------------------------------------------
ระบบแยกสิทธิ์ออกเป็น 2 ชั้น และบังคับใช้ที่ฝั่งเซิร์ฟเวอร์ทั้งคู่
(การซ่อนปุ่มในหน้าเว็บเป็นแค่ความสะดวก ไม่ใช่ตัวป้องกันจริง)

ชั้นที่ 1 — ขอบเขตข้อมูล (เห็นสถานประกอบการใดได้บ้าง)
  Inspector / Safety Officer : เห็นเฉพาะสถานประกอบการที่ได้รับมอบหมาย
  Supervisor                 : เห็นทุกแห่งในสาขาที่ตนสังกัด
  Manager / Administrator    : เห็นทั้งหมดทุกสาขา

ชั้นที่ 2 — สิทธิ์การกระทำ (ทำอะไรได้บ้าง)
  ความสามารถ                Inspector  Safety  Supervisor  Manager  Admin
  บันทึกผลตรวจ                  ✓        ✓         -          -       ✓
  รับทราบการแจ้งเตือน            ✓        ✓         ✓          ✓       ✓
  ส่งต่อหัวหน้างาน               -        ✓         ✓          -       ✓
  ปิดการแจ้งเตือน                -        -         ✓          ✓       ✓
  อัปเดตการแก้ไข                 -        ✓         ✓          ✓       ✓
  จำลองการตรวจจับ (AI)           -        ✓         ✓          ✓       ✓
  จัดการ/จัดซื้ออุปกรณ์           -        -         -          ✓       ✓
  รีเซ็ตข้อมูลระบบ                -        -         -          -       ✓

บัญชีทดลองและขอบเขตที่เห็น
  inspector@safecheck.demo   เห็น 2 จาก 6 แห่ง  (Riverlight Bistro, Garden Table)
  safety@safecheck.demo      เห็น 3 จาก 6 แห่ง
